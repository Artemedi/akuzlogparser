# AKUZ Log Explorer 4.8.0 — Windows portable

Для Windows 10/11 x64. Python, pip, Paramiko и криптографические библиотеки уже включены в EXE. Устанавливать или скачивать зависимости на рабочем компьютере не нужно. Удалённый сервер требуется только для SSH/SMB: локальные `.log` и готовые отчёты работают без подключения к серверу. Приложение всё равно использует локальный браузерный адрес `127.0.0.1`.

## Первый запуск

1. Полностью распакуйте ZIP в доступную для записи папку, например `D:\AKUZLogExplorer`.
2. Для SSH/SMB заполните ConnectConf.cfg рядом с AKUZLogExplorer.exe; для локальных файлов конфиг можно оставить примером.
3. Запустите `AKUZLogExplorer.exe`. Откроется браузер с `http://127.0.0.1:8765/`.
4. Выберите журналы и создайте отчёты. Дата подставляется из имени `YYYYMMDD_*.log`.
5. Для остановки нажмите Ctrl+C в открытой консоли. Закрытие вкладки браузера само по себе сервер не останавливает.

**Локальные журналы:** выберите «Источник → Локальный .log / папка», введите полный путь, например D:\AKUZ\Logs или D:\AKUZ\Logs\20260923_server.log, и нажмите «Список файлов» либо «Последний лог». Путь относится к компьютеру с запущенным EXE, не к удалённому браузеру. Обрабатываются только .log, каталог не обходится рекурсивно, исходники не меняются. Настройка ConnectConf.cfg не нужна. Путь запоминается только на время работы локального сервиса. UNC-пути обслуживаются отдельным источником Windows · SMB.

При первом запуске EXE распакует файлы интерфейса рядом с собой. Там же хранятся `downloads/`, `reports/`, `cache/`, `data/`. Сохраняйте всю папку приложения для переноса отчётов и офлайн-аналитики. EXE не устанавливает системную службу и не требует прав администратора.

Для SSH заранее проверьте ключ сервера и добавьте его в `%USERPROFILE%\.ssh\known_hosts` (например, штатным клиентом Windows OpenSSH). Неизвестные ключи приложение автоматически не принимает. Для SMB/UNC используются права текущего пользователя Windows.

## Диагностика длительного разбора

Во время операций Explorer пишет `diagnostics/performance.txt` рядом с EXE (резервные файлы `.1`, `.2`). Каждая запись содержит локальный таймштамп с часовым поясом, имя этапа, `status=start|done|failed|progress`, `elapsed_s` и числовые метрики. Каждые 50 000 событий выводится прогресс разбора/объединения/аналитики, поэтому видно, где задача задерживается. Не записываются текст событий, медицинские данные, пути исходников, пароли или токены. Папка не входит в Git и не отдаётся веб-сервером; при пересылке всё равно проверьте содержимое самостоятельно.

Сравните длительности `source.fetch` (получение), `generate.parse` (парсинг + распознавание), `generate.catalog` (сериализация индекса), `combined.stream` (потоковая общая выборка, внутри `report.generate`), `analytics.ingest` и `analytics.export`. Старые данные **не профилируются задним числом**: для замера нужен следующий реальный запуск операции. Повторный выбор неизменённого закэшированного источника может переиспользовать готовый отчёт и не выполнить парсинг; чтобы измерить полную генерацию, выбирайте новый исходный файл либо новое содержимое. Для уже созданных HTML-отчётов есть `scripts/refresh_report_ui.py`, см. README_EXPLORER.md.

В v4.8.0 этап `source.ssh.transfer` содержит `compression=0/1` и среднюю скорость МиБ/с; передача, хеширование и запись локального снимка учитываются вместе. Встроенная SSH-компрессия не включается без изменения `[ssh] compression = true` в вашем конфиге. Replicated A/B на рабочих fixed-prefix журналах подтвердил заметное уменьшение wall/socket RX, но одновременно существенно повысил measured CPU родительского `sshd`, поэтому default остаётся выключенным. При большом объёме сравнивайте число символов `raw_chars`, а не только количество событий; длительности вложенных этапов не суммируйте с родительскими.

### Надёжность кэша и SSH-prefetch в v4.8.0

Для multi-source fresh build временный derived spool хранится только на время
текущей операции и удаляется после неё; постоянный B-lite sidecar не создаётся.
Публикация отчётов и inventory защищены блокировкой и recovery-intent, а один
app-root обслуживается одним экземпляром Explorer. Для локальных файлов строгую
перепроверку исходника перед warm reuse можно явно включить переменной среды
`AKUZ_VERIFY_LOCAL_SOURCE_SHA=1`; это добавляет полный SHA-проход и по умолчанию
выключено.

### Process-prefetch для нескольких SSH-файлов

На Windows portable при двух и более выбранных SSH-файлах v4.8.0 по
умолчанию перекрывает разбор текущего snapshot с получением следующего.
Используется один отдельный Windows child process maximum; child создаётся
приостановленным и включается в KILL_ON_JOB_CLOSE Job Object до начала
исполнения. Сырые данные не передаются через IPC: parent получает только
ограниченные метаданные и самостоятельно перепроверяет snapshot полным
SHA-256 и Windows file identity.

Локальные файлы и SMB/UNC работают прежним последовательным путём.
Для аварийного отключения оптимизации:

```powershell
$env:AKUZ_PHASE11_PROCESS_PREFETCH = '0'
.\AKUZLogExplorer.exe
```

Удалите/сбросьте эту переменную, чтобы снова использовать default-on режим.
Некорректное значение считается ошибкой конфигурации, а не молча
интерпретируется.

### Опциональный Phase 12 delta/resume

Текущая ветка после v4.8.0 содержит проверенный **default-OFF** режим
докачивания выросшего Linux/SSH журнала:

```powershell
$env:AKUZ_PHASE12_DELTA_RESUME = '1'
.\AKUZLogExplorer.exe
```

Он используется только при наличии доказанного предыдущего snapshot:
совпадают SSH host/path и device/inode, локальный файл проходит SHA-256,
а resume начинается с сохранённых `stored_bytes`. Новый snapshot принимается
только после SHA-256 всего удалённого принятого префикса. Legacy cache без
proof metadata идёт полным fetch; обычная ошибка delta также откатывается на
полную bounded-загрузку. При включённом Phase 12 process-prefetch Phase 11
временно не используется.

Чтобы вернуться к стандартному v4.8 поведению, удалите переменную или задайте
`AKUZ_PHASE12_DELTA_RESUME=0`. Опубликованный v4.8.0 Release этой
невыпущенной opt-in возможностью не изменён.

## Обновление

При обновлении с v4.7.1 (или более ранней v4) закройте приложение и замените только `AKUZLogExplorer.exe`. Сохраните свой `ConnectConf.cfg` и каталоги данных. При следующем запуске интерфейс обновится, конфиг останется прежним. Не распаковывайте конфиг-пример поверх своего заполненного файла.

Если конфиг отсутствует, EXE создаст пример `ConnectConf.cfg`, который нужно заполнить. Для запуска на другом порту: `AKUZLogExplorer.exe --port 8766`. Для запуска без открытия браузера: `AKUZLogExplorer.exe --no-browser`.

**Один каталог приложения — один запущенный экземпляр.** Даже при другом `--port` второй экземпляр с той же папкой `cache/` завершится с сообщением «Каталог AKUZ Explorer уже занят другим экземпляром». Закройте прежний EXE перед новым запуском. `cache/.akuz-instance.lock` — служебный файл, не удаляйте его для «разблокировки»: система сама освобождает блокировку после завершения процесса. Другую независимую папку portable можно запускать отдельно; её отчёты и кэш не объединяются.

Архив включает `BUILD_INFO.json` с коммитом исходников и версиями сборки. Контрольная сумма ZIP поставляется отдельно в `SHA256SUMS.txt`. Заполненный конфиг и рабочие журналы в поставку не входят.

EXE также доступен отдельным файлом в релизе: при первом запуске он создаст конфиг-пример и файлы интерфейса рядом с собой. ZIP удобнее для первого знакомства — в нём уже есть конфиг и эта инструкция. Текущая сборка не подписана Authenticode.
