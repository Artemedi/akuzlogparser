# История изменений AKUZ Log Explorer

## Post-v4.6.0 ? Phase 8 Error Probe (main, before next release)

- Numeric-only counters for recognize_error paths: call count, scanned
  prefix chars, 24k truncation, ASCII, exception, serialization, first-line
  generic error, and unrecognized messages. No raw text is logged.
- Public API and HTML/JS files unchanged; Phase 8 is instrumentation,
  NOT a demonstrated speed improvement.
- Paired Windows synthetic benchmarks show approximately 1-2% cost.
- Two exploratory micro-optimizations (ASCII replace, JS translate)
  are not integrated: no reproducible benefit.

## После v4.6.0 — Phase 7 Shared Fold (в main, до нового релиза)

- Один `casefold(message)` на событие в `generate()` вместо
  двух независимых преобразований в `classify()` и `extract_duration()`.
  Самостоятельные вызовы обеих функций и `read_input()` совместимы.
- `generate.parse` дополнен отдельной метрикой `fold_s`; сравнивайте
  суммарное время, так как состав `classify_s`/`duration_s` поменялся.
- Дифференциальные тесты и побайтовые сравнения отчётов;
  на двух парных Windows-бенчмарках синтетики около 6% выигрыша.
- Это изменение ветки main после тега v4.6.0, отдельный релиз не создан.

## 4.6.0 — 2026-09-25

- Классификатор больших сообщений переведён на find-based поиск с точной проверкой границ и пробелов; исходный прототип исправлен по обязательным `\\s+`. На синтетике 50 000 событий генерация ускорена в 1,60 раза, побайтовая идентичность 68 файлов отчёта подтверждена. Добавлены отдельные differential и end-to-end тесты.

- Ускорена сборка многострочных сообщений; устранено повторное копирование растущих строк.
- Классификатор, извлечение длительностей и распознавание ошибок пропускают дорогостоящие поиски, если в тексте нет обязательных маркеров; приоритет и правила категорий сохранены.
- Убрано создание большой временной подстроки при выделении первой строки сообщения.
- Дополнена диагностика числом символов обработанных событий и размером самого крупного события.
- Добавлены синтетические бенчмарки и проверки идентичности каталога и сырых частей отчёта с базовой версией.
- Общая выборка по умолчанию передаёт объединённые события напрямую генератору без записи и повторного чтения гигантского промежуточного JSONL; старый JSONL-путь сохранён для CLI/пользовательского генератора. Проверены даты, строки, отпечатки ошибок и побайтовая идентичность выходных HTML/JS.
- Для статических локальных и Windows/SMB-снимков SHA-256 считается при копировании, без второго полного чтения файла. При усечении активного снимка SHA-256 пересчитывается по фактически сохранённым байтам.
- SSH-получение разбито в диагностике на подключение, инвентаризацию, stat до/после, передачу и необязательное усечение/повторный хеш; во время передачи прогресс каждые 64 МиБ, скорость МиБ/с. Добавлена **выключенная по умолчанию** SSH-компрессия `ssh.compression` для контролируемого сравнения с учётом CPU сервера.

- Для Unicode со сменой границ слова (включая U+0345 и меняющие длину casefold) классификатор возвращается к прежнему regex.
- На Windows проверено 131 860 сравнений классификации со старым кодом; 68 файлов тестового отчёта совпали побайтово. Ускорение 1,60× для 50 000 синтетических смешанных событий и 3,57× для синтетических длинных сообщений не следует переносить на реальные журналы без замера.
- Эксперимент с общим `casefold()` отклонён: измеримого выигрыша не было; изменения интерфейсов функций не включены.

## 4.5.0 — 2026-09-25

- Почасовая плотность: суточный профиль 00–23, хронология, переключение между событиями, распознанными ошибками и средним за день; фильтрация часа по всем датам или конкретному дню.
- История снимков одного источника сворачивается по умолчанию, без суммирования событий.
- Удалена устаревшая галочка «Включая отчёты v4»: очистка кэша из интерфейса сохраняет все готовые отчёты.
- Скрипт обновления интерфейса уже созданных v4-отчётов без повторного разбора логов и изменения каталога данных.
- Регрессионные тесты JavaScript/Python.
- Поэтапная диагностика производительности в diagnostics/performance.txt: получение, парсинг, сериализация каталога, объединение, индекс ошибок и экспорт; начало/конец/секунды, редкие отметки каждых 50 000 событий, ротация 3 МБ × 3 файла, без текста событий.

## 4.4.0 — 2026-09-23

- Новый источник «Локальный .log / папка»: абсолютный путь к файлу или каталогу на компьютере с Explorer, без SSH/SMB/конфига; нерекурсивное чтение .log только на чтение.
- Локальные файлы проходят прежний workflow: список, выбор до 30, «Последний лог», снимки растущего файла, даты, отчёты, аналитика и повторное использование кэша.
- Локальные оригиналы не удаляются очисткой кэша. Добавлены Python/JS-тесты и packaged Windows smoke test локального импорта.

## 4.3.1 — 2026-09-23

- Библиотека отчётов визуально группирует исторические снимки одного зарегистрированного источника; показывает последний и предыдущие снимки отдельно.
- Одинаковые имена с разных серверов и путей не объединяются; аналитический индекс и дедупликация не изменены.
- Добавлен тест группировки снимков и разделения независимых источников.

## 4.3.0 — 2026-09-23

- Portable Windows 10/11 x64: EXE включает Python, Paramiko, криптографические библиотеки и интерфейс; рабочему компьютеру не нужна установка зависимостей.
- Конфиг и данные располагаются рядом с EXE. Обновление ресурсов сохраняет пользовательский конфиг, скачанные журналы и отчёты.
- Даты автоматически берутся из `YYYYMMDD_*.log`, включая старые отчёты в аналитике. Ручная корректировка приоритетна.
- Аналитика заблокирована до окончания обработки всей пачки, в том числе при прямом HTTP-запросе.
- Исправлена миграция SQLite без `relative_day`; текущая схема индекса — 5, инвентаря — 4.
- Проверено повторное использование неизменённых файлов и полное скачивание нового снимка после роста файла.
- Добавлены Windows CI, проверка доставляемого EXE, манифест сборки и контрольные суммы. Готовые файлы можно отправить прямо в черновик релиза, минуя хранение артефактов Actions.
- Документация приведена к текущему поведению; удалены устаревшие утверждения о встроенном демонстрационном журнале и датах из mtime.
