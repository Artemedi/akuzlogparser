# Phase 9 — One supported app process per report/cache root

Status: **BOUNDED SERVER-ENTRY HARDENING**, not a low-level inventory transaction. Application code candidate from base `b6902c8`, tests pending Windows/portable and exact final integration SHA. No published GitHub Release change.

`akuz_app.main()` now acquires a stable, OS-backed nonblocking lock on `cache/.akuz-instance.lock` BEFORE updating bundled UI assets and opening its loopback HTTP server. The file remains present after exit; ownership is its live OS lock, never the presence or age of the pathname. The handle remains open until `serve_forever()` ends, a port binding error or other startup exception; `os._exit`/kill releases the OS lock when the process dies. Windows uses msvcrt 1-byte `LK_NBLCK`, Linux uses fcntl `flock LOCK_EX|LOCK_NB`. A second process with a different port but SAME app-root fails visibly instead of building reports concurrently. The lock pathname contains no credentials or source text, and is not deleted by cache clear.

This narrow guard makes supported instances mutually exclusive but **does not make `akuz_store.save_store` multiprocess-safe** for scripts, old releases ignoring this lock, direct API invocation, simultaneous users with different app roots but shared external LocalDest, or third-party writers. `scripts/probe_phase9_inventory_race.py` is intentionally expected to reproduce a lost update when two unguarded direct writers share an inventory. The open low-level fix remains a cross-process read/modify/write transaction with freshness validation. Do not change the probe to claim PASS by merely moving the fixed temporary filename.

Synthetic subprocess acceptance: two *actual* `akuz_app.main` servers on distinct ports against one disposable root; second refuses while first runs. Kill first; second acquires without deleting lockfile. Bind-error path releases ownership. Check standalone historical `--self-test` only writes its separate fixture root; production startup is protected. Windows Python and frozen combo, real source SHA, full suite and independent review on exact rebased commit are required before adoption.

Also OPEN, independently: physical power-loss/fsync durability; adversarial symlink/path races; cleanup/retention of abandoned sensitive stage/intent/spools; old app versions that don't honor the lock. Do not claim global inventory serializability or full Phase 9 closure from server exclusivity alone.
