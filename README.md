# AKUZ Log Explorer · akuzlogparser

Самостоятельный локальный парсер и HTML-интерфейс для файловых журналов приложения **АКУЗ (AKUZ)**. Текущая версия — **4.2.1**. Обрабатывает `.log`, загруженные по SSH с Linux-сервера или из доступной Windows-папки SMB/UNC, и строит отчёты для просмотра в браузере.

## Возможности

- Просмотр событий, поиск, фильтры и переход к полному тексту записи.
- Отдельные отчёты по файлам и общая выборка при заданных датах источников.
- Аналитика распознанных ошибок из уже обработанных и зарегистрированных отчётов.
- Группировка по типу ошибки, точному нормализованному шаблону или семейству.
- Диаграммы повторений по дням и часам, переход от группы к исходному событию.
- Относительная шкала `D+0`, `D+1`, если календарная дата неизвестна; назначение даты первой записи ранее обработанному источнику через интерфейс аналитики.
- Локальный кэш, повторное использование неизменённых снимков и чтение готовых HTML-отчётов офлайн.

Источники — файловые журналы приложения АКУЗ. Системные журналы Linux, Windows Event Log, журналы PostgreSQL и исходники VCLib в анализ не входят.

## Быстрый запуск

Для готового [portable-пакета Windows x64](README_PORTABLE.md) Python и установка зависимостей не нужны: распакуйте ZIP, заполните конфиг и запустите `AKUZLogExplorer.exe`.

Инструкции ниже относятся к запуску **из исходников**: нужен Python 3.9+ и Paramiko из `requirements.txt`.

### Windows

1. Скопируйте `ConnectConf.example.cfg` в `ConnectConf.cfg`, если своего конфига ещё нет, и заполните параметры источника.
2. Запустите `START_EXPLORER.bat`. При отсутствии Paramiko скрипт предложит установку.
3. Откройте `http://127.0.0.1:8765/`, получите список файлов, выберите журналы и создайте отчёты.

Для SMB/UNC нужны права текущего пользователя Windows на чтение сетевой папки. Подробная настройка — в [инструкции запуска](README_START_HERE.md).

### Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
# Выполните только при отсутствии собственного ConnectConf.cfg:
cp -n ConnectConf.example.cfg ConnectConf.cfg
# Заполните ConnectConf.cfg перед загрузкой журналов.
python akuz_app.py --no-browser
```

Откройте `http://127.0.0.1:8765/`. Порт можно изменить: `python akuz_app.py --port 8766 --no-browser`. Остановка — `Ctrl+C`.

### Отчёт из локального файла

```bash
python akuz_html_explorer.py /path/to/application.log -o /path/to/report
```

Если дата первой записи достоверно известна, добавьте `--date YYYY-MM-DD`. Созданный `index.html` можно открыть в браузере. Такой отдельно созданный отчёт автоматически не регистрируется в библиотеке аналитики приложения.

## Аналитика ошибок и даты

Создайте отчёты через приложение и откройте **«Аналитика ошибок»** (`errors.html`). Пока выбранные файлы скачиваются и обрабатываются, аналитика недоступна; блокировка действует также при прямом открытии URL. По умолчанию ошибки сгруппированы по типу; для более узкой выборки выберите точный шаблон. Нажмите на группу, чтобы увидеть динамику и исходные события.

Внутри журнала может быть только время. Для имён `YYYYMMDD_*.log` дата первой записи определяется автоматически, включая старые отчёты в аналитике. Ручная корректировка имеет приоритет. Для остальных имён укажите дату или используйте относительную шкалу. Дата изменения файла не считается достоверной датой события. Коррекция даты в аналитике не переписывает исходный `.log` и ранее созданный HTML-отчёт.

Аналитика строится локально из зарегистрированных отчётов, без повторного скачивания журналов. Группировка и дедупликация имеют ограничения: общий тип исключения не доказывает общую причину, а неоднозначные события исключаются из временных графиков. Подробности — в [README_ANALYTICS.md](README_ANALYTICS.md).

## Офлайн и обновление

Готовые отчёты открываются без Python-сервиса. Для общей аналитики сохраните структуру проекта с `reports/` и сгенерированными файлами `data/`. Загрузка новых журналов и изменение дат требуют запущенного локального приложения. Portable-версия запускается через `AKUZLogExplorer.exe`; зависимости включены внутрь.

При обновлении сохраняйте свой `ConnectConf.cfg` и каталоги `reports/`, `cache/`, `downloads/`, `data/`. После обновления исходников откройте `errors.html` через локальный сервис: индекс аналитики обновится из существующих отчётов.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `akuz_app.py` | Локальный HTTP-сервис и API |
| `akuz_log_parser.py` | Разбор записей АКУЗ |
| `akuz_html_explorer.py` | Генерация HTML-отчётов |
| `akuz_analytics.py` | Группировка ошибок, даты и индекс SQLite |
| `akuz_fetch.py` | Получение снимков по SSH |
| `akuz_windows.py` | Чтение файловых журналов Windows |
| `akuz_store.py` | Инвентарь отчётов и кэш |
| `index.html`, `errors.html`, `event.html`, `*.js`, `style.css` | Интерфейс браузера |
| `tests/` | Автоматические проверки |

## Проверки

```bash
python -m unittest discover -s tests -v
# При установленном Node.js:
node --test tests/test_app_controls.cjs
```

Тесты используют временные файлы и локальный HTTP-сервер; доступ к рабочему серверу АКУЗ не требуется. Для проверки синтаксиса JavaScript при установленном Node.js: `node --check errors.js`.

Заполненный конфиг, исходные журналы, кэш и отчёты исключены через `.gitignore`: они могут содержать пароли и персональные данные.

## Сборка Windows EXE

Готовый пакет создаётся workflow **Windows portable** (ручной запуск в GitHub Actions). Артефакт `AKUZLogExplorer-windows-x64` содержит ZIP и SHA-256; он публикуется только после проверки готового EXE на Windows.

Для локальной сборки на Windows x64 с Python 3.12:

```powershell
python -m pip install -r requirements-build.txt
python scripts/build_portable.py
python scripts/smoke_portable.py dist/AKUZLogExplorer-windows-x64.zip
```

Python и интернет нужны на машине сборки; пользователю готового ZIP они не нужны. Заполненный `ConnectConf.cfg` и рабочие данные не включаются в архив. При обновлении заменяйте только EXE, сохраняя конфиг и каталоги данных.
