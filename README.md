# AKUZ Log Explorer 4.6.0

Локальное приложение для загрузки и разбора файловых журналов АКУЗ: HTML-отчёты, поиск событий, повторяющиеся ошибки и графики по дням/часам. Источники — файловые .log приложения АКУЗ по Linux/SSH, Windows/SMB или из локального файла/каталога. Системные журналы и VCLib в проект не входят.

## Запуск без установки Python

Скачайте **AKUZLogExplorer-windows-x64.zip** из [релиза v4.6.0](https://github.com/Artemedi/akuzlogparser/releases/tag/v4.6.0), распакуйте его в доступную для записи папку и запустите `AKUZLogExplorer.exe`. `ConnectConf.cfg` заполняется **только для SSH/SMB**; локальный `.log` или каталог можно выбрать без конфигурации.

Portable-версия для Windows 10/11 x64 включает Python, Paramiko и криптографические библиотеки. Дополнительно скачивать зависимости не нужно. Откроется браузер с `http://127.0.0.1:8765/`. Доступ к серверу требуется только для получения новых журналов. [Инструкция portable-версии](README_PORTABLE.md).

## Основные возможности

- Список удалённых или локальных файлов, выбор до 30 журналов, снимки активно растущих `.log`.
- Дата первой записи из имени `YYYYMMDD_*.log`, с возможностью ручного изменения.
- Отдельные HTML-отчёты и общая выборка при наличии дат всех источников; компактный 24-часовой профиль с переключением на хронологию, числом распознанных ошибок и средним за день.
- Поиск по событиям и полному тексту, фильтры по дню/файлу, переход к исходным строкам.
- Аналитика уже обработанных отчётов: группы по типу, точному шаблону или семейству ошибки; календарные и относительные графики.
- Повторное использование неизменённых файлов; выросший журнал скачивается новым снимком целиком, история снимков сворачивается в библиотеке.
- Просмотр готовых отчётов офлайн. Аналитика через сервис открывается после окончания обработки всей выбранной пачки.
- Диагностический журнал `diagnostics/performance.txt`: начало/конец этапов, длительности и прогресс каждые 50 000 событий без текста исходных журналов. Очистка кэша сохраняет готовые отчёты.

## Локальные журналы без SSH/SMB

В интерфейсе выберите **Источник → Локальный .log / папка**, укажите **абсолютный путь** к файлу .log или каталогу с такими файлами на ПК, где запущен EXE (например, D:\AKUZ\Logs), и нажмите «Список файлов» или «Последний лог». В папке берутся только файлы .log непосредственно внутри неё, без рекурсии; можно выбрать до 30. Имя YYYYMMDD_*.log задаёт дату первой записи. Оригиналы читаются только на чтение; отдельные снимки и отчёты остаются рядом с EXE. Для локального источника не нужны настройки SSH и SMB. Системные журналы не поддерживаются. [Подробнее](README_START_HERE.md#локальный-файл-или-каталог).

## Конфигурация и данные

Конфиг-пример — [ConnectConf.example.cfg](ConnectConf.example.cfg). Заполненный `ConnectConf.cfg`, исходные журналы и отчёты остаются локально и не входят в Git или релиз.

| Путь рядом с EXE или исходниками | Назначение |
| --- | --- |
| `ConnectConf.cfg` | Параметры SSH/SMB; для локального источника не нужен |
| `downloads/` | Скачанные снимки `.log` |
| `reports/` | Готовые отчёты с собственными данными |
| `cache/inventory.json` | Реестр загрузок и отчётов |
| `cache/error_analytics.sqlite` | Перестраиваемый индекс ошибок, схема 5 |
| `data/` | Статический снимок общей аналитики |
| `diagnostics/performance.txt` | Локальная хронология этапов, длительности и счётчики без исходных записей; текущий файл и два резервных, порог ротации 3 МиБ |

При обновлении EXE сохраняйте конфиг и все каталоги данных. **Старые HTML-отчёты не получают новую верстку автоматически:** для них есть `scripts/refresh_report_ui.py` (предпросмотр и `--apply`), см. [руководство отчётов](README_EXPLORER.md#обновление-уже-созданных-отчётов). Подробности — в [руководстве запуска](README_START_HERE.md).

## Как выяснить причину долгого разбора

Запустите разбор в v4.6.0 и откройте **`diagnostics/performance.txt` рядом с EXE**. Сопоставьте `elapsed_s` для `source.fetch` (получение), `generate.parse` (разбор и запись частей), `generate.catalog` (индекс HTML), `combined.stream` (потоковая общая выборка внутри `report.generate`) и `analytics.ingest`/`analytics.export` (аналитика). Во время большого разбора появляются отметки прогресса каждые 50 000 событий. Остановившийся `status=start` без `done` означает незавершённый этап, а не обязательно ошибку. См. [инструкцию по диагностике](README_START_HERE.md#диагностика-медленной-обработки).

## Что изменилось в v4.6.0

Многострочные записи собираются один раз; классификация больших сообщений использует быстрый буквальный поиск с сохранением прежних правил Unicode и приоритетов ошибок. Общая выборка теперь передаётся генератору напрямую, без гигантского промежуточного JSONL; второй проход по исходным снимкам остаётся. SSH дополнительно показывает скорость и фазы передачи, а необязательная компрессия выключена по умолчанию. Для локального и SMB-файла SHA-256 считается при копировании; после усечения активного снимка вычисляется по сохранённым байтам. Данные существующих отчётов и заполненный конфиг не требуется удалять.

Результаты синтетических бенчмарков и условия сравнения — [PERFORMANCE_NOTES.md](PERFORMANCE_NOTES.md). Скорость передачи SSH при `compression=true` на рабочем сервере не измерялась.

## Запуск из исходников

Python 3.9+; для SSH нужен Paramiko. На Windows можно использовать `START_EXPLORER.bat`. В Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
# Только если своего конфига ещё нет:
cp -n ConnectConf.example.cfg ConnectConf.cfg
# Заполните конфиг только если используете SSH или SMB.
python akuz_app.py --no-browser
```

Откройте `http://127.0.0.1:8765/`. Другой порт: `python akuz_app.py --port 8766`. Остановка: Ctrl+C.

Отдельный HTML-отчёт из локального файла:

```bash
python akuz_html_explorer.py /path/to/application.log -o /path/to/report --date 2026-09-23
```

Для этого CLI дата задаётся через `--date`; если неизвестна — опустите аргумент. CLI-отчёт автоматически не регистрируется в библиотеке приложения. [Работа с отчётами](README_EXPLORER.md).

## Разработка и сборка

```bash
python -m unittest discover -s tests -v
node --test tests/test_app_controls.cjs tests/test_hourly_view.cjs
```

Windows EXE собирается на Windows x64 с Python 3.12:

```powershell
python -m pip install -r requirements-build.txt
python scripts/build_portable.py
python scripts/smoke_portable.py dist/AKUZLogExplorer-windows-x64.zip
```

Workflow **Windows portable** запускается вручную в GitHub Actions (не автоматически при `push`). Он тестирует приложение, собирает EXE, проверяет готовый ZIP и публикует артефакт `AKUZLogExplorer-windows-x64`. Если включить `draft_release`, вместо артефакта создаётся черновик релиза с EXE, ZIP и SHA-256; этот режим не использует квоту артефактов Actions. `BUILD_INFO.json` внутри ZIP указывает версию, коммит и зависимости сборки. [Архитектура и выпуск](README_PROJECT.md).

## Ограничения

Докачивания только новых байтов и сжатия SSH-потока пока нет. Снимок растущего файла ограничен размером, но не является транзакционным. Распознавание ошибок основано на текстовых признаках; группировка не устанавливает причину сбоя. [Методика аналитики](README_ANALYTICS.md).
