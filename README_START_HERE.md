# AKUZ Log Explorer v4.2 · журналы AKUZ и аналитика ошибок

Локальный интерфейс для AKUZ-журналов из Linux-каталога по SSH. Пакет исходников не содержит медицинских журналов или демонстрационного отчёта. Вы можете открывать отчёты в браузере без доступа к серверу; для кнопок SSH и управления кэшем приложение нужно запустить через BAT.

## Быстрый запуск Windows

1. Полностью распакуйте ZIP, например в `D:\AKUZ_Explorer_v4_1`. Не запускайте BAT внутри ZIP. Если переходите с v3/v4, **сохраните отдельно свой заполненный `ConnectConf.cfg`** и перенесите его в новую папку. Не затирайте собственный конфиг примером из ZIP.
2. Заполните `ConnectConf.cfg` как в примере ниже. Если используете пароль, файл конфигурации остаётся локально и содержит его открытым текстом; ограничьте доступ к папке через Windows ACL. Лучше использовать SSH-ключ.
3. Проверьте ключ SSH-сервера, если ещё не подключались с этой учётной записи Windows: `ssh -p 22 ina@1.1.1.1`. Сверьте fingerprint с администратором. Не принимайте неизвестный ключ без проверки.
4. Запустите двойным щелчком `START_EXPLORER.bat`. Нужен Python **3.9+**. Если нет Paramiko, BAT предложит установку через pip; для первого раза нужен доступ к PyPI или внутреннему зеркалу.
5. Откроется `http://127.0.0.1:8765/`. Нажмите **«Список файлов»**, дождитесь списка, выберите нужные строки, проверьте дату первой записи в поле справа и нажмите **«Создать отчёты по выбранным файлам»**.
6. Для закрытия сервера нажмите Ctrl+C в консоли BAT. Файлы отчётов остаются в `reports/` и могут открываться офлайн через их `index.html`.

## Три основных действия

**↓ Последний лог:** привычная кнопка. Получает самый свежий по времени изменения удалённый файл. Дата первой записи берётся из имени `YYYYMMDD_*.log`; mtime для неё не используется. Если такой же снимок уже сохранён в v4, повторное скачивание и повторный отчёт не создаются.

**▾ Показать файлы / ▴ Свернуть файлы:** дополнительный ручной переключатель панели. После успешной загрузки и перехода к отчёту список файлов автоматически сворачивается; после ошибки остаётся открытым.

**↻ Список файлов:** показывает подходящие по `file_pattern` файлы непосредственно в `remote_log_dir`: имя, mtime, размер, признак локального кэша. Фильтры «с/по» работают по **дате изменения файла на сервере** (mtime в календарной дате, рассчитанной локальным ПК), НЕ по внутренним датам AKUZ. Можно выбрать один файл, несколько или все видимые (до 30 за один запуск).

**Дата первой записи:** поле возле каждого выбранного файла. Исходный формат AKUZ содержит время (`HH:mm:ss.mmm`), но не календарную дату. Для имён `YYYYMMDD_*.log` дата заполняется автоматически. Исправьте её, если файл создан вчера, ротировался после полуночи или содержит несколько дней. Переход через полночь внутри файла парсер учитывает. Если имя не содержит корректной даты и поле пустое, отдельный отчёт показывает `D+0`, `D+1`. Общая хронологическая выборка создаётся только при заданной дате у всех включаемых источников.

**⌫ Очистить кэш:** без галочки удаляет только отмеченные в `cache/inventory.json` скачанные **v4-файлы** вида `akuz_v4_*`, не затрагивая готовые отчёты, другие локальные файлы и Linux-сервер. С галочкой «Включая отчёты v4» после подтверждения удаляет также созданные и зарегистрированные v4-отчёты. Исходный встроенный отчёт v2/v3 и любые неучтённые файлы остаются. Это удаление локальных копий: не ставьте галочку, если нужный отчёт существует только здесь.

## Как работает дедупликация

- Удалённый снимок идентифицируется сервером, портом, пользователем, полным путём, размером, mtime и идентификатором inode (если поддерживается GNU find). Для кэшированного скачивания сверяются размер и SHA-256 локальной копии.
- Повторно выбранный неизменённый файл с той же назначенной датой переиспользует старый HTML-отчёт. При смене даты исходный файл может быть повторно использован **без SSH**, а отчёт строится с новой датой.
- Идентичные байты разных источников не доказывают повтор события. Новые отчёты и общая выборка разделяют источники по серверу и полному пути; только повтор того же установленного источника переиспользует отчёт.
- **Повторяющиеся текстовые сообщения не удаляются**: одинаковый текст двух реальных событий ещё не означает дубликат. При перекрытии разных файлов после ротации отдельные совпадающие события могут сохраниться — без доказательства побайтового пересечения опасно стирать их автоматически.
- Старые v3 отчёты/файлы не импортируются в индекс v4 автоматически; архив v4 не переписывает вашу прежнюю папку.

## Что получится при выборе нескольких файлов

В `reports/` появятся **отдельные HTML-отчёты** по каждому уникальному исходному файлу. При наличии дат для всех — дополнительно **«Общая выборка»**: события в выбранном порядке по датам первой записи, с фильтрами «Дата / день» и «Файл журнала». Исходный текст сохраняется, карточка события показывает исходный файл и исходные номера строк. У каждого отчёта собственный каталог `data/`, поэтому старые события не пристыковываются к новым.

Страница «Мои отчёты» — ссылки на ранее созданные v4-отчёты. У одного дня может быть **несколько разных файлов**; дата не является уникальным ключом события или файла.

## ConnectConf.cfg

```ini
[ssh]
host = 1.1.1.1
port = 22
username = ina
password =
sudo_password =
key_file =

[logs]
remote_log_dir = /srv/pg_data/log
file_pattern = *.log
local_dest =
base_date =
```

- `local_dest =` пусто → `downloads/` рядом с BAT. Если задан внешний каталог, очистка удаляет **только** отслеживаемые v4-файлы внутри него; остальные файлы не трогаются.
- `password` — пароль SSH при парольной авторизации; `sudo_password` используется только для sudo и при пустом значении наследует SSH-пароль. Если оба пусты, допускается `sudo -n` по уже настроенным правам; пароль никогда не встраивается в Linux-команду.
- `base_date` из v3 оставлен для совместимости конфигурации, но выбор даты возле каждого файла имеет приоритет в новом рабочем процессе. Кнопка «Последний лог» определяет дату из имени `YYYYMMDD_*.log`.
- `file_pattern = *.log` значит только обычные `.log`. `*.gz` как сжатый текстовый `.log.gz` в этой версии не разбирается; `.jsonl.gz` поддержан HTML-генератором как архив событий, но не как удалённый текстовый лог.

## Где лежат данные

```text
AKUZ_Log_Explorer_v4_1/
  START_EXPLORER.bat
  ConnectConf.cfg         # секреты, не делитесь им
  index.html              # встроенный пример просмотра
  akuz_app.py             # API на 127.0.0.1
  akuz_fetch.py           # SSH find/stat/head
  akuz_store.py           # инвентарь, SHA и очистка
  akuz_html_explorer.py
  akuz_log_parser.py
  downloads/              # созданные v4 локальные снимки
  cache/inventory.json    # только метаданные, без паролей
  reports/v4_.../         # отдельные HTML-отчёты
```

## Безопасность и ограничения

- HTTP слушает только `127.0.0.1`, проверяет `Host` и `Origin` изменяющих запросов, не выдаёт `ConnectConf.cfg`, исходный `.log`, `inventory.json`, Python-код или файлы из `downloads/`.
- При скачивании оригинал на Linux не изменяется; скрипт **не создаёт `/tmp` и не делает `chmod 644`**. Для чтения каталога/файла используется обычный пользователь, при необходимости sudo через stdin.
- **Режим «Снимок активного журнала» включён автоматически.** По SSH выясняется текущий размер файла, затем читается ровно зафиксированное количество байт. Если сервер дописал данные в конец во время чтения, это **не ошибка** и операция не ждёт бесконечно дальнейших записей. Если файл уже вырос с момента отображения списка, перед формированием отчёта проводится повторная инвентаризация.
- Если снимок активный и закончился посередине физической строки, незавершённый хвост удаляется только из локальной копии; в отчёт попадают завершённые строки. На сервере ничего не обрезается. Завершённый неизменный файл без последнего `\n` сохраняется целиком.
- При ротации с заменой inode/устройства, удалении либо усечении во время передачи снимок отклоняется, `.part` удаляется. Это **не транзакционная согласованность**: изменение содержимого на месте при том же inode и без уменьшения размера не всегда можно обнаружить; если требуется строгий снимок, предварительно остановите запись или используйте штатную ротацию логов.
- Новые снимки одного растущего журнала сохраняются **отдельными версиями**. При построении общей выборки не выбирайте одновременно более старый и более новый снимки **одного и того же файла**: их содержимое перекрывается, автоматического побайтового вычитания префикса пока нет.
- Пользовательские даты нужно подтверждать по именованию/ротации файлов или другим доказательствам; `mtime` и локальное системное время не являются достоверной датой событий.
- Все отчёты, список логов, Request ID и тексты могут содержать медицинские/персональные сведения. Архив и папку Explorer храните в защищённом месте.
- Журналы другого формата, не похожего на исходный AKUZ, этот парсер может не разобрать. Предел — 30 выбранных файлов за запуск, чтобы случайно не скачать весь серверный архив.

### Проверка и отладка

Если BAT пишет о Python/Paramiko — запустите в PowerShell `py -3 -m pip install -r requirements.txt` и повторите. Если получаете `Unknown server`, подключитесь через стандартный `ssh` и проверьте fingerprint. Если файл ротирован или усечён — обновите список. Обычный рост файла больше не требует обновлять список вручную. При занятом 8765 запустите `py -3 .\akuz_app.py --port 8766`.

Реальное SSH-подключение к вашему серверу разработчиком не выполнялось; автоматические тесты использовали локальные файлы и моделирование SSH-ответов. В среде тестирования проверка через Chromium/localhost блокировалась политикой браузера, поэтому окончательно проверьте кнопки на Windows.


## Файловые логи Windows-службы (SMB / UNC)

На компьютере Windows обеспечьте чтение сетевой папки с журналами службы AKUZ (например,
`\\SERVER\AKUZLogs`) от имени запущенного пользователя; предпочтительна выделенная
read-only шара вместо `C$`. В `ConnectConf.cfg` добавьте:

```ini
[windows]
enabled = true
log_dir = \\SERVER\AKUZLogs
file_pattern = *.log
local_dest =
```

Запустите `START_EXPLORER.bat`, выберите «Windows · SMB / UNC» и нажмите
«Список файлов» / «Последний лог». Файлы Windows читаются только на чтение,
без установки службы, WinRM, копирования в remote /tmp и выполнения команд на Windows-сервере.
Снимки активных журналов принимают дописывание в конец; частично записанная
последняя строка исключается. Если Windows-служба открыла лог без file-sharing read,
Explorer покажет ошибку доступа: потребуется изменить режим ведения журнала/шару.
При закрытии сервиса Explorer отчёты по-прежнему можно открыть локально через index.html.
Windows Event Log в этот релиз не входит.


Windows TraceLogger: поддержаны строки вида user 'name' HH:mm:ss.fff: message
(и Category: user 'name' HH:mm:ss.fff: message). Windows-журналы другого
формата нужно проверить на реальном образце перед использованием отчёта.


## Аналитика ошибок v4.2

Нажмите «▥ Аналитика ошибок» в шапке Explorer или «Аналитика этой ошибки ↗»
в карточке распознанного исключения нового отчёта. Откроется errors.html:
поиск группы, семейство, график по дням/часам, ограничение периода и
исходные события со ссылкой на сохранённый HTML-отчёт. Статический снимок
аналитики работает офлайн по file:// при сохранении каталогов data/ и reports/.
Прочтите README_ANALYTICS.md для точных правил дедупликации и дат.
Собираются только *.log АКУЗа из выбранной оператором папки.


## Аналитика ошибок v4.2.1 (после обработки нескольких .log)

Откройте «Аналитика ошибок» в работающем локальном Explorer.
В левой колонке доступен выбор: «По типу ошибки» — агрегирует одинаковые
классы исключения, «По точному шаблону» — конкретная нормализованная
ошибка, «По семейству» — широкие тематические категории. Нажатие на
группу открывает диаграмму и исходные события с переходом к записи.

Если видите «С датой: 0», это означает отсутствие подтверждённой
календарной даты первой записи в метаданных ранее обработанных .log,
а не отсутствие времени события. График автоматически переключается
на D+0/D+1 (день/час ВНУТРИ каждого журнала). Для календарной диаграммы
откройте блок «Календарные даты исходных журналов» и подтвердите дату
первой записи нужного источника, используя оригинальный лог или правила
ротации; не подменяйте её mtime. Пересоздавать отчёты и скачивать
журналы заново не требуется.

В режиме file:// готовые графики работают без Python, но подтверждение
дат через localhost API недоступно — запустите START_EXPLORER.bat
и откройте http://127.0.0.1:8765/errors.html.


## Даты из имён и завершение обработки

По принятой схеме именования `20260923_*.log` означает дату первой записи 2026-09-23. Эта дата подставляется в списке файлов, используется кнопкой «Последний лог» и применяется к ранее зарегистрированным отчётам в аналитике. Ручная корректировка имеет приоритет. Неверные даты вроде `20260230_*.log` не принимаются. mtime остаётся датой изменения для фильтра списка файлов.

Аналитика заблокирована до завершения загрузки и обработки всей выбранной пачки, включая обновление индекса. Вторая вкладка и прямой URL также проверяют состояние сервиса. Офлайн-копия отражает последний сохранённый снимок и не связана с запущенным сервисом.

Перед использованием кэша перечитываются удалённые размеры и метаданные. Неизменённый файл переиспользуется; при росте скачивается новый ограниченный по размеру снимок целиком. Докачивания только новых байтов пока нет. Изменение mtime или идентификатора файла тоже влияет на повторное использование; одинаковые размер и mtime не доказывают побайтовую неизменность на сервере.
