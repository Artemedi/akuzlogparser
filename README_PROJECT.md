# akuzlogparser 4.5.0 — архитектура и разработка

Самостоятельный проект анализа файловых журналов АКУЗ. Локальное приложение с HTML-интерфейсом, Python-ядром и portable-сборкой Windows x64. Проект не зависит от VCLib и не собирает системные журналы. Доступны SSH, SMB/UNC и локальный путь к .log/папке.

## Хранение и пути

В исходниках корень данных — каталог приложения. В EXE это каталог `sys.executable`, независимо от текущего рабочего каталога и временной папки распаковки PyInstaller. Интерфейс обновляется из встроенных ресурсов при запуске EXE. Существующий `ConnectConf.cfg` никогда не заменяется автоматически.

`cache/inventory.json` хранит регистрацию загрузок и отчётов, `reports/` — исходные данные HTML-отчётов. SQLite и корневой статический экспорт аналитики производны от зарегистрированных отчётов. При миграции проверяется и номер схемы, и наличие `relative_day`, поскольку старые версии могли записать номер новой схемы без изменения таблицы.

Публикация отчёта идёт через временный каталог `.building` с последующим переименованием. Долгие операции выполняются фоновым потоком; `State.busy` снимается после окончания обработки пачки. При нескольких файлах строятся отдельные HTML-отчёты, затем читается и сериализуется объединённая `.jsonl`-выборка и отдельно генерируется её HTML-отчёт. Это **повторная обработка событий**, поэтому при расследовании времени учитывайте оба `report.generate` и `combined.merge`. HTTP-чтение аналитики и изменение её дат согласованы с запуском операций через блокировку состояния. Офлайн-копия показывает последний сохранённый снимок.

## Даты и идентичность

В интерфейсе/обработке файлов `YYYYMMDD_*.log` определяет дату первой записи. Ручная дата приоритетна. Для старых отчётов дата из имени применяется в аналитике без перезаписи исходных частей. Отдельный CLI-генератор использует явный `--date`.

Идентичность источника и кэш опираются на сервер/компьютер, путь, размер, mtime и идентификатор файла; локальная копия проверяется по SHA-256. Повторная проверка метаданных источника предшествует использованию кэша. Рост вызывает полное скачивание нового снимка. Побайтовая докачка и сжатие передачи не реализованы.

## Диагностика производительности (4.5.0)

`akuz_diagnostics.event()` пишет только заранее предусмотренный этап, `status`, локальный timestamp с часовым поясом и **числовые** метрики, без динамических имён файлов, путей, текста сообщений, секретов или исключений. Контекст `phase()` пишет `start` / `done` либо `failed` с `elapsed_s`, измеренным через `perf_counter()`. Сбор диагностических записей не должен прекращать обработку при ошибке записи файла. Путь — `<app_root>/diagnostics/performance.txt`, резервные `.1`/`.2`; директория исключена из Git и не включена в HTTP-allowlist. В портативном режиме `app_root()` — папка EXE.

Основные внешние интервалы: `worker.perform_build`, `source.fetch`, `report.generate`, `combined.merge`, `analytics.refresh`. В локальной оптимизации после 4.5.0 `generate.parse` также сообщает `raw_chars` и `max_event_chars` (символы, не байты), не включая тексты событий. Изменены только внутренние способы сборки многострочности и запуска текстовых регулярных выражений, а не формат HTML или аналитики. Вложенные: `generate.parse` (включая `shard_write_s`), `generate.catalog`, `analytics.inventory`, `analytics.ingest`, `analytics.export`, `analytics.overview`. Прогресс записи событий — каждые 50 000; события старых запусков не профилируются. Не суммируйте `report.generate` с его вложенными этапами или `analytics.refresh` с `analytics.ingest`. Внешние зависимости SSH/SMB проверяются на машине оператора, а не при CI на синтетических данных.

Для статистически полезного сравнения фиксируйте объём `input_bytes`, `events`, конечный `elapsed_s`, нагрузку на диск и то, создавалась ли общая выборка. `generate.parse` измеряет комплексную работу (чтение, классификацию, формирование `raw_*.js`), не время одного вызова регулярного выражения. [Пошаговая интерпретация](README_START_HERE.md#диагностика-медленной-обработки).

## Проверки

```bash
python -m unittest discover -s tests -v
node --test tests/test_app_controls.cjs tests/test_hourly_view.cjs
```

Python-тесты проверяют парсер, SSH/SMB/локальный источник, дедупликацию, даты, миграцию SQLite, HTTP, portable-пути, ограниченный журнал диагностики и обновление UI сохранённых отчётов без изменения `data/`. Node-тесты проверяют блокировку аналитики, группировку снимков, локальный путь и компактный почасовой профиль с фильтрацией на модели DOM; это не полноценный визуальный браузерный тест.

## Сборка и выпуск

1. Обновите `akuz_version.py`, видимые подписи интерфейса и текущую документацию. Исторические changelog сохраняйте как историю.
2. Выполните тесты и отправьте коммит.
3. Запустите workflow **Windows portable** на нужном коммите/ветке. Он использует Windows x64 и Python 3.12; PyInstaller закреплён в `requirements-build.txt`.
4. Дождитесь проверки готового EXE. Тест запускает его из каталога с кириллицей/пробелами и без Python в PATH, проверяет native crypto, синтетический разбор, HTTP, импорт локального .log, сохранение конфига и расположение данных.
5. Скачайте артефакт и проверьте SHA-256. `BUILD_INFO.json` внутри ZIP должен указывать выпускаемый коммит.
6. Создайте тег и GitHub Release на этом коммите, прикрепите EXE, ZIP и `SHA256SUMS.txt`.

Альтернатива при выпуске: включите вход `draft_release` workflow. После успешных проверок он загрузит файлы прямо в черновик релиза на коммите сборки, минуя квоту артефактов Actions. Проверьте контрольные суммы и опубликуйте черновик. Для этого workflow имеет разрешение `contents: write`; публикация остаётся отдельным шагом.

Сборка включает только явно перечисленные ресурсы и конфиг-пример. `akuz_diagnostics.py` включается в EXE через импорт `akuz_app.py`; файл `diagnostics/performance.txt` создаётся только при работе приложения, а не пакуется в архив. Личные данные из `ConnectConf.cfg`, `downloads/`, `cache/`, `reports/`, `data/` не должны попадать в пакет. Текущая сборка EXE не подписана Authenticode.

Проверки не обращаются к рабочему серверу АКУЗ. Доступ к конкретному SSH/SMB-источнику проверяется отдельно в его окружении.
