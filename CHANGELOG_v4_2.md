# v4.2 — AKUZ Error Analytics

> Историческая запись. Актуальное поведение версии 4.3.0 описано в [README](README.md) и [общем changelog](CHANGELOG.md).

- Самостоятельная страница errors.html с локальными графиками по дням и часам
  и переходами к полному событию в сохранённом HTML-отчёте.
- Группировка по классу исключения, нормализованному тексту и первому stack frame;
  отдельно семейство ошибок сериализации и поиск групп по подстроке.
- Инкрементальный SQLite индекс, читающий только уже обработанные отчёты,
  статический экспорт data/analytics.js и data/error_<fingerprint>.js для file://.
- Защита от двойного подсчёта идентичных исходных событий при повторных снимках
  и объединённых отчётах. Неопределённые пересечения исключены из графика.
- Недатированные события доступны в общем списке без выдуманной даты.
- В карточке новых отчётов появилась кнопка аналитики конкретной ошибки.
- Источники ограничены файлами *.log самого AKUZ; никакие Windows Event Log,
  PostgreSQL/Linux system logs или VCLib не входят в проект.
- Ветка v4.1 не заменяется: сохранены загрузка, выбор дат, кэш и offline HTML.


## Уточнения дедупликации и календарных дат

- Индекс аналитики schema v3: источник разделяется по host/path,
  один лишь одинаковый SHA-256 на разных серверах не означает повтор события.
- При изменении подтверждённой даты источника в инвентаре аналитика
  пересчитывается, даже когда содержимое HTML-отчёта не меняется.
- В панели выбора файлов дата первой записи теперь пустая по умолчанию;
  mtime отображается только как подсказка, а не автоматически выбранная дата.
- Источник без явно заданной календарной даты остаётся в списке совпадений,
  но не участвует в графиках по дням и календарным часам.

- Повторное использование HTML-отчётов и общих выборок теперь учитывает
  сервер и исходный путь; разные источники с одинаковыми байтами не
  склеиваются автоматически.


## v4.2.1 — Error Analytics usability hotfix

- Убраны визуально пустые/сжатые элементы списка групп.
- Выбор ширины группировки: тип ошибки / точный шаблон / семейство.
- График относительных дней/часов для журналов без подтверждённой
  календарной даты; D+N не смешивается с реальным календарём.
- Назначение даты для уже обработанных источников через localhost API
  без повторного получения .log и без изменения исходных событий.
- Исправлено использование последней даты для всех источников
  объединённого отчёта: дата теперь привязана к каждому источнику.
- Индекс аналитики schema v4 автоматически пересоздаётся из ранее
  сохранённых HTML-отчётов; исходные журналы не перечитываются.

## Исправление миграции индекса аналитики

- При обновлении старого SQLite-индекса добавляется столбец `relative_day`, затем индекс перестраивается из зарегистрированных отчётов.
- Восстанавливается и индекс, ошибочно помеченный версией 4 без нового столбца. Исходные журналы, отчёты и инвентарь сохраняются.
- После миграции обновляется статический снимок аналитики, в том числе для пустой библиотеки.


Даты из имён, блокировка аналитики и portable EXE выпущены в [4.3.0](CHANGELOG.md).
