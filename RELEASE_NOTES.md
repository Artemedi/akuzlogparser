# AKUZ Log Explorer 4.6.0 — Windows 10/11 x64 portable

Релиз для анализа **только файловых журналов AKUZ `.log`**. Windows portable EXE включает Python, Paramiko и необходимые зависимости; системные журналы Windows/Linux и VCLib приложение не собирает.

## Что изменилось после v4.5.0

- **Отдельные отчёты:** многострочное сообщение собирается один раз. Классификация использует быстрый буквальный поиск с проверкой границ слов и исходный regex для Unicode-случаев, где `casefold` может изменить длину/границы. Прежние категории, порядок правил, исходные строки и error fingerprint сохранены.
- **Общая выборка:** объединённые события поступают в генератор напрямую, без создания и повторного чтения большого промежуточного JSONL. Отдельные отчёты и повторный разбор файлов для общей выборки по-прежнему выполняются. CLI/пользовательский генератор сохраняет прежний путь.
- **SSH:** запись длительности подключения, инвентаризации, `stat` до/после, передачи, условного усечения/повторного хеширования. Во время получения — прогресс каждые 64 МиБ и скорость МиБ/с, `compression=0/1`. Компрессия Paramiko **выключена по умолчанию**; параметр `[ssh] compression = true` можно отдельно испытать с контролем CPU сервера. Серверные gzip/zstd и инкрементальная докачка не реализованы.
- **Локальные и Windows/SMB снимки:** SHA-256 считается при копировании, без второго чтения статического файла. При усечении активного файла digest пересчитывается по сохранённым байтам.
- Расширены регрессионные тесты и документация по `diagnostics/performance.txt` и измерению одинаковых снимков.

## Подтверждённые проверки и ограничения

На синтетическом наборе 50 000 событий (64,7 МБ) сравнение regex/find показало 8,98 → 5,61 с (около 1,60×) на одной Windows-машине. На отдельном синтетическом наборе длинных событий наблюдалось около 3,57×. Генерируемые HTML/JS сравнивались **побайтово**; differential-тест классификации проверяет 131 860 строк, включая сложные Unicode-случаи. Это **не** замер ускорения реального 644-МБ рабочего лога и не обещание конкретного времени обработки. Изменение скорости SSH при `compression=true` на рабочем сервере не измерялось.

## Установка и обновление

Скачайте `AKUZLogExplorer-windows-x64.zip`, полностью распакуйте и запустите `AKUZLogExplorer.exe`. Для обновления v4.5.0 **закройте работающий EXE и замените только сам `AKUZLogExplorer.exe`** рядом с существующими `ConnectConf.cfg`, `downloads/`, `reports/`, `cache/` и `data/`. **Не заменяйте ваш заполненный конфиг конфигом-примером из ZIP.** Старые готовые отчёты сохраняются; интерфейс старых папок `reports/v4_*` при необходимости обновляется отдельным скриптом `scripts/refresh_report_ui.py` (без перезаписи их данных).

Первое подключение SSH требует доверенного ключа сервера в `known_hosts`. Для локальных `.log` настройки SSH/SMB не нужны. Адрес браузера: `http://127.0.0.1:8765/`. Диагностика хранится рядом с EXE в `diagnostics/performance.txt` и не должна содержать содержимого исходных журналов.

## Файлы выпуска

- `AKUZLogExplorer-windows-x64.zip` — EXE, конфиг-пример, README_PORTABLE и `BUILD_INFO.json` с версией/точным Git-коммитом.
- `AKUZLogExplorer.exe` — отдельно для обновления существующей установки.
- `SHA256SUMS.txt` — SHA-256 EXE и ZIP.

В ZIP нет заполненного `ConnectConf.cfg`, реальных логов, медицинских данных, кэша или отчётов. EXE не подписан Authenticode. История и методика измерений: `CHANGELOG.md` и `PERFORMANCE_NOTES.md`.
