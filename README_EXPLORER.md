# AKUZ Log Explorer 4.5.0 — работа с отчётами

Готовый отчёт — папка с `index.html`, `event.html`, интерфейсом и частями данных в `data/`. Он открывается в браузере без Python и без подключения к серверу. Переносите всю папку, а не только HTML-файл. Рабочие журналы и демонстрационные события в поставку не включены.

## Локальные журналы

Источник «Локальный .log / папка» позволяет задать абсолютный путь к файлу или папке на компьютере с запущенным EXE, без SSH и SMB. Выбираются только обычные .log на верхнем уровне; копии попадают в downloads/, а исходные файлы сохраняются без изменений. Формирование и повторное использование HTML-отчётов, дата из имени и аналитика работают аналогично SSH/SMB. [Подробности](README_START_HERE.md#локальный-файл-или-каталог).

## Просмотр

1. Откройте отчёт через «Мои отчёты» в приложении или его `index.html` напрямую.
2. Используйте текстовый поиск и фильтры компонентов, категорий, времени, дня и исходного файла.
3. Поиск по полному тексту последовательно читает локальные части записей. На больших отчётах он может занять время; предусмотрена отмена.
4. Нажмите на событие, чтобы увидеть полный текст, Request ID, пользователя и исходные номера строк.
5. Из карточки можно копировать текст и ссылку, переходить к соседним событиям или событиям того же Request ID.

Категории определяются по текстовым признакам: в исходном формате может не быть уровня ERROR/INFO/WARN. Они не являются подтверждённой серьёзностью события или диагнозом причины.

## Дни и несколько файлов

При загрузке через приложение дата первой записи подставляется из имени `YYYYMMDD_*.log`; её можно исправить вручную. Переход через полночь увеличивает день. Если календарная дата неизвестна, отображаются относительные дни `D+0`, `D+1`.

Для нескольких выбранных файлов создаются отдельные отчёты. Если у всех есть даты, создаётся также общая выборка с фильтром исходного файла. Одинаковые даты или одинаковый текст не делают события разных источников дубликатами. Кнопка «Очистить кэш» удаляет скачанные копии журналов, но **сохраняет готовые отчёты**.

### Плотность событий по часам

По умолчанию диаграмма объединяет одинаковые часы всех дат в **суточный профиль (00–23)**. Показатель переключается между суммарным числом событий, числом распознанных ошибок и средним количеством событий на день. Среднее делит сумму на число представленных календарных дней; неполные сутки специально не достраиваются. Подсказка показывает разбивку по датам; выбор часа в профиле фильтрует события этого часа **во все дни**. Вид «Хронология» возвращает отдельные даты и часы для расследования конкретного интервала. В нём среднее за день неприменимо и переключается на число событий.

Исторические снимки одного зарегистрированного источника в разделе «Мои отчёты» скрыты под сворачиваемым заголовком; их числа событий не суммируются. Общая выборка по выбранным .log по-прежнему имеет собственный набор событий: при ручном выборе перекрывающихся снимков нельзя предполагать автоматического исключения повторных событий.

### Обновление уже созданных отчётов без повторного разбора

Исходники UI распространяются в каждом статическом отчёте отдельными файлами. После изменения исходников старые папки `reports/v4_*/` **сами не обновляются**. Из корня репозитория используйте скрипт, передав каталог установленного Explorer, в котором находится `reports/`:

```powershell
python scripts/refresh_report_ui.py "D:/AKUZLogExplorer"
python scripts/refresh_report_ui.py "D:/AKUZLogExplorer" --apply
```

Первая команда только перечисляет подходящие отчёты; вторая **по одному файлу** заменяет `index.html`, `index.js`, `app_controls.js`, `style.css` в подходящих папках `reports/v4_*` с проверкой наличия `data/catalog.js`. Содержимое `data/`, кэш, конфиг и журналы не переписываются. Это не единая транзакция обновления всех отчётов: при прерывании запускайте скрипт повторно. Остановите Explorer на время обновления, затем запустите его и обновите страницу браузера (Ctrl+F5). Это обновляет локальные v4-отчёты, а не EXE: для постоянной поставки интерфейса нужно отдельно собрать новую portable-версию.

Общая выборка и аналитика ошибок — разные представления. Аналитика имеет собственную дедупликацию и работает по всей зарегистрированной библиотеке. Не смешивайте перекрывающиеся снимки одного файла вручную, ожидая автоматического вычитания байтов в общей выборке.

## Аналитика ошибок

Кнопка «Аналитика ошибок» открывает группы и графики по ранее обработанным отчётам. Во время получения и обработки пачки она заблокирована. Назначение даты старому источнику в аналитике изменяет её календарные расчёты, но не переписывает дату в старом HTML-отчёте.

Для офлайн-аналитики сохраняйте корневые `errors.html`, `errors.js`, `data/` и `reports/`. Одна отдельно перенесённая папка отчёта сохраняет просмотр событий, но не всю библиотеку аналитики. [Описание аналитики](README_ANALYTICS.md).

## Генерация из локального файла

Эти команды относятся к исходникам и требуют Python. Portable EXE обслуживает интерфейс загрузки и просмотра; отдельный CLI-генератор запускается из исходников.

```bash
python akuz_html_explorer.py application.log -o report --date 2026-09-23
python akuz_html_explorer.py events.jsonl.gz -o report
```

`--date` — дата первой записи в формате `YYYY-MM-DD`. В CLI дата из имени автоматически не подставляется. Если дата неизвестна, не указывайте аргумент. `--chunk-size` задаёт число событий в части полного текста (по умолчанию 1000, допустимо 10–10000); `--top` — размер рейтингов повторов и длительностей.

Для Markdown/JSONL-отчёта:

```bash
python akuz_log_parser.py application.log -o parsed --date 2026-09-23
```

Полный список параметров: `python akuz_log_parser.py --help` и `python akuz_html_explorer.py --help`. Отдельные CLI-отчёты автоматически не добавляются в `cache/inventory.json`; для общей библиотеки создавайте отчёты через приложение.

## Ограничения

- Поддерживаются заголовки АКУЗ Linux `HH:mm:ss.fff,component,session,user: message` и Windows TraceLogger `user 'name' HH:mm:ss.fff: message`, включая многострочное продолжение.
- Исходные `.log.gz` не являются входом текстового парсера; `.jsonl.gz` поддерживается как архив уже разобранных событий.
- Возможность копирования из `file://` зависит от разрешений браузера; при отказе выделите текст вручную.
- Полнотекстовый поиск и таблицы крупных отчётов требуют памяти браузера; наличие EXE не снимает эти ограничения.
- Файлы отчёта могут содержать персональные данные и полные запросы. Обращайтесь с ними как с исходным журналом.
